## Directory Purposes

**backend/**
- Purpose: FastAPI server + business logic
- Contains: Python async code, SQLite schema, market data simulation/integration, API routes
- Key files:
  - `app/main.py` — Entry point; lifespan management, route registration, static serving
  - `app/api/` — HTTP endpoints grouped by domain (health, watchlist, portfolio, chat)
  - `app/db/` — Database initialization, schema, all query functions
  - `app/market/` — Market data abstraction, cache, simulator, Massive API client
  - `pyproject.toml` — uv project config with dependencies and test settings

**frontend/**
- Purpose: Next.js TypeScript source (currently empty; will be built to static/)
- Contains: React components, pages, styling
- Key files: TBD (frontend agent responsible)

**static/**
- Purpose: Built frontend served by FastAPI via StaticFiles mount at root `/`
- Contains: HTML, JS, CSS assets from Next.js static export
- Generated: By Next.js build process; not checked into git directly (only `_next/` stub exists)

**test/**
- Purpose: E2E and integration tests using Playwright
- Contains: Browser automation tests, docker-compose config for test environment
- Key files: `docker-compose.test.yml` — separate compose file for test infra

**db/**
- Purpose: Runtime location for SQLite database file
- Contains: `finally.db` (created at runtime, gitignored)
- Runtime: Mounted as Docker volume `-v finally-data:/app/db`

**planning/**
- Purpose: Shared documentation for agents (not code)
- Contains:
  - `PLAN.md` — Full specification (source of truth)
  - `MARKET_DATA_SUMMARY.md` — Market data component deep-dive
  - `codebase/` — Generated by GSD agents (ARCHITECTURE.md, STRUCTURE.md, etc.)
  - `archive/` — Historical decisions and notes

**scripts/**
- Purpose: Container orchestration (start/stop) without docker-compose
- Contains: Bash scripts for macOS/Linux; PowerShell scripts for Windows (TBD)
- Usage: `./scripts/start_mac.sh` builds and runs container with volume + env file

## Naming Conventions

**Files:**
- `main.py` — Application entry point
- `models.py` — Pydantic or dataclass model definitions
- `schema.py` — Database schema SQL
- `queries.py` — Database query functions
- `interface.py` — Abstract base classes
- `cache.py` — Caching layers
- `stream.py` — SSE or async streaming
- `{component}_client.py` — External API clients (e.g., `massive_client.py`)
- `test_{module}.py` — Unit tests for a module

**Directories:**
- `api/` — FastAPI route routers
- `db/` — Database layer (schema, queries, connections)
- `market/` — Market data subsystem (sources, cache, models, streaming)
- `tests/` — Test suite (mirrors app structure)

**Functions & Variables:**
- Async functions: `async def function_name(...) -> ReturnType`
- Query functions: `async def get_*() / set_*() / delete_*()`
- Route handlers: Use Pydantic BaseModel for request/response types
- Private functions/modules: Prefix with `_` (e.g., `_generate_events()`, `_iso_now()`)

**Classes:**
- Market data sources: `*DataSource` (e.g., `SimulatorDataSource`, `MassiveDataSource`)
- Models: PascalCase (e.g., `PriceUpdate`, `TradeRequest`, `LLMResponse`)
- Exceptions: PascalCase, rarely used (prefer returning error dicts)

## Where to Add New Code

**New API Endpoint:**
- Create file in `backend/app/api/{domain}.py` (or add to existing file)
- Define Pydantic request/response models at top
- Create APIRouter with `@router.get/post/delete()` handlers
- Import and include in `backend/app/main.py`: `app.include_router({router})`
- Tests: `backend/tests/api/test_{domain}.py` [optional, not yet created]

**New Database Query:**
- Add function to `backend/app/db/queries.py`
- Follow naming: `async def get_*() / set_*() / delete_*()`
- Use `get_db()` context manager, execute SQL, return typed dict or list
- Add corresponding test if logic is complex

**New Market Data Source (e.g., real API):**
- Create `backend/app/market/{source_name}.py`
- Implement `MarketDataSource` ABC (all abstract methods required)
- Update `backend/app/market/factory.py` to instantiate based on env var
- Add tests in `backend/tests/market/test_{source_name}.py`

**New Market Data Model:**
- Add dataclass or Pydantic model to `backend/app/market/models.py`
- Implement `to_dict()` for JSON serialization if needed
- Use throughout cache and streaming

**Utilities & Helpers:**
- Shared functions: `backend/app/db/queries.py` or `backend/app/market/` modules
- Don't create top-level `utils.py` file; keep code co-located with consumers
- Private helpers (prefixed `_`) in the module where used

**Tests:**
- Unit tests: `backend/tests/{domain}/{test_*.py}` (mirror app structure)
- Fixtures: Add to `backend/tests/conftest.py` (shared across tests)
- Mock objects: Define in test file or conftest
- Use pytest async support: `pytest-asyncio`, `asyncio_mode = "auto"`

**Documentation:**
- Code comments: Explain WHY, not WHAT (code is self-documenting)
- Docstrings: Module-level and class-level (PEP 257)
- Planning docs: Add to `planning/` directory (agent-consumable markdown)

## Special Directories

**db/ (Runtime):**
- Purpose: Volume mount point for SQLite persistence
- Generated: `finally.db` created by backend on first request
- Committed: `.gitkeep` only (DB file is gitignored)
- Persistence: Docker named volume `-v finally-data:/app/db` keeps data across container restarts

**static/ (Generated):**
- Purpose: Next.js static export output, served by FastAPI
- Generated: By frontend build process
- Committed: `_next/` stub exists to show directory exists; actual build output not committed
- Serving: FastAPI mounts at root `/`; app.mount("/", StaticFiles(...), name="static")

**tests/ (Test Infrastructure):**
- Purpose: E2E tests separate from backend unit tests
- Generated: Test artifacts (screenshots, videos) on failure
- Committed: Test source files + `docker-compose.test.yml`
- Running: Requires Docker; spins up separate test compose stack

**planning/codebase/ (Generated):**
- Purpose: GSD agent-generated documentation
- Generated: By `/gsd-map-codebase` command
- Committed: YES (reference for future agents)
- Files: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, STACK.md, INTEGRATIONS.md, CONCERNS.md
