<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> POST /api/chat | User-supplied message text enters the system |
| backend -> LLM API | Outbound call to OpenRouter with user content |
| LLM response -> backend | External LLM returns JSON that drives trade execution |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | ChatRequest.message | mitigate | Pydantic BaseModel validates input is a string; no SQL injection risk (parameterized queries via aiosqlite) |
| T-03-02 | Tampering | LLM response JSON | mitigate | Pydantic `model_validate_json()` rejects malformed responses; trades go through same validation as manual trades (cash/share checks) |
| T-03-03 | Denial of Service | LLM timeout | mitigate | Exception handler catches all LLM failures, returns fallback message with HTTP 200 (CHAT-08) |
| T-03-04 | Information Disclosure | API key in logs | accept | LiteLLM handles auth headers internally; OPENROUTER_API_KEY only in .env (gitignored). Low risk in single-user local app. |
| T-03-05 | Spoofing | Prompt injection via user message | accept | System prompt is hardcoded; user message is last. Simulated environment with fake money -- zero real-world impact. |
</threat_model>
