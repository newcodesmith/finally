Append new test classes to `backend/tests/test_chat.py`. The key challenge is testing auto-execution: mock mode returns empty trades/watchlist_changes, so we need to either (a) monkeypatch the LLM call to return a constructed LLMResponse with trades, or (b) test the execution logic directly.

**Approach: Monkeypatch the chat endpoint's LLM call path.**

For auto-execution tests, set `LLM_MOCK` to `"false"` locally in the test, then monkeypatch `litellm.completion` (or the import inside the function) to return a fake response containing trades/watchlist_changes. This tests the full pipeline end-to-end.

However, since the `from litellm import completion` is inside the function body, monkeypatching requires either:
- Patching `litellm.completion` at module level before the endpoint imports it
- Or: creating a helper that constructs a mock `completion` return value

**Simpler approach:** Create a helper function that builds a mock litellm response object:

```python
class _MockChoice:
    def __init__(self, content):
        self.message = type("M", (), {"content": content})()

class _MockResponse:
    def __init__(self, content):
        self.choices = [_MockChoice(content)]
```

Then monkeypatch `litellm.completion` (import litellm at test module level) to return `_MockResponse(json_str)`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM response -> trade execution | External LLM output drives real state changes (positions, cash) |
| LLM response -> watchlist mutation | External LLM output modifies watchlist |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | ChatRequest.message | mitigate | Pydantic BaseModel validates input is a string; parameterized queries |
| T-03-02 | Tampering | LLM response JSON | mitigate | Pydantic `model_validate_json()` rejects malformed; trades validated by execute_trade (cash/share checks) |
| T-03-03 | Denial of Service | LLM timeout/failure | mitigate | Broad except catches all failures, returns HTTP 200 fallback (CHAT-08). Tested in TestLLMFailureHandling. |
| T-03-05 | Elevation | LLM requesting excessive trades | mitigate | Each trade goes through same validation as manual trades (cash check, share check). No elevated privileges. Tested in TestFailedTrades. |
</threat_model>
